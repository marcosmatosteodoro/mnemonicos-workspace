Decisões fixadas:
- Dinheiro: `formatBrlFromCents(4990)` = "R$ 49,90" com espaço comum (4990 → "R$ 49,90"; 0 → "R$ 0,00"; 5 → "R$ 0,05"; 123456 → "R$ 1.234,56"; 2147483647 → "R$ 21.474.836,47"). `parseBrlToCents("49,90")` = 4990; aceita "49", "49,9", "0", "0,00" e "1.234,56" (ponto só como milhar de 3 dígitos); texto vazio, não numérico, "49,999" ou acima de 2147483647 centavos → `null`; um valor negativo numérico ("-5") devolve centavos negativos (-500), que o formulário ENVIA para o servidor recusar.
- O formulário não bloqueia o envio por regra de negócio: campos de texto vazios seguem como digitados e preço vazio é omitido do corpo; quem recusa nome vazio, preço vazio ou negativo é o servidor (TASK-063-007), e a tela exibe a recusa junto ao campo. A única recusa local é a de preço preenchido que não é número (letras, "49,999"): "Informe o preço em reais, como 49,90.", sem requisição. Campo obrigatório leva `aria-required`.
- Edição: Descrição, Prova/concurso e Disciplina esvaziadas viram `null` no `PATCH` (a TASK-063-007 aceita `null` para limpar).
- Remover é oferecido a todo EDITOR e ADMIN; a recusa de quem não é autor é do servidor e a mensagem aparece no diálogo.
- Dois estados decidem o ramo do detalhe e têm nome fixo para serem grepáveis: `isEditing` (setter `setIsEditing`) e `isRemoving` (setter `setIsRemoving`); enquanto um está ativo ou uma operação está em voo, as ações concorrentes ficam `disabled`.
